# gRPC reference

Two identical definitions exist: `payment-service/src/main/proto/payment.proto` and `subscription-service/src/main/proto/payment.proto`. They define unary `ProcessPayment` and `GetPaymentHistory` in `PaymentGrpcService`; generated source files are **not found in repository** (normally generated at build time). `PaymentGrpcServiceImpl.processPayment` maps to `PaymentService.createPayment`, sends one response, completes; `getPaymentHistory` maps customer payments to repeated history (`payment-service/src/main/java/com/ayush/subscription/payment/grpc/PaymentGrpcServiceImpl.java`). It does not call `onError`, validate malformed UUIDs, or catch service exceptions.

`PaymentGrpcClient.processPayment` creates a **blocking** stub and calls the unary method (`subscription-service/src/main/java/com/ayush/subscription/subscription/client/PaymentGrpcClient.java`). `GrpcClientConfig.paymentChannel` hard-codes plaintext `localhost:9090`; no deadline, TLS, metadata, load balancing, discovery, retry, or error mapping is configured. Payment server port is 9090 (`payment-service/src/main/resources/application.yml`). `GetPaymentHistory` has a server method but no client call in repository.
